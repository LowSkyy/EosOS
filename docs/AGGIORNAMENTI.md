# Aggiornamenti automatici

Stato: **fatti dal lato del programma** (8 nov 2026). **Non ancora attivi per gli utenti**: manca un posto pubblico dove pubblicare le versioni (vedi «Cosa serve a te»).

## Come funziona
- Plugin ufficiale `tauri-plugin-updater`. EosOS scarica un `latest.json` (versione, note, indirizzo e **firma** del programma di installazione), lo confronta con la versione in uso e, se c'è una più nuova, la mostra nelle Impostazioni → Generale → **Aggiornamenti** con «Controlla ora» e, se c'è, «Installa la versione X».
- **Firma obbligatoria.** Il programma di installazione è firmato con una chiave privata (minisign) che resta solo a te; la chiave pubblica sta in `tauri.conf.json`. Prima di installare il plugin verifica la firma: un file firmato con **un'altra chiave** è rifiutato («The signature was created with a different key…»), un file senza firma valida pure. Quindi anche un sito di aggiornamenti compromesso non può far installare codice non tuo.
- **Solo https.** Il plugin rifiuta un indirizzo del feed non in https nelle build di produzione. L'indirizzo è fisso in `tauri.conf.json` (`plugins.updater.endpoints`): la pagina non può cambiarlo.
- **Niente parte da solo.** L'impostazione «Cerca aggiornamenti all'avvio» (`general.update_auto`) è **spenta di default**; accesa, 20 secondi dopo l'avvio fa **una** richiesta del feed e ricorda l'esito, **senza scaricare né installare**. L'installazione parte solo dal pulsante. Su Windows l'installatore (modalità `passive`) chiude EosOS e lo aggiorna.
- Rete: la sola richiesta è al feed (indirizzo, versione del sistema e di EosOS nell'intestazione standard del plugin); non si inviano dati dell'utente.
- I comandi `update_status`, `update_check`, `update_install` si accettano solo dalla finestra Impostazioni (`cmdpolicy.rs`).

## Cosa serve a te (decisioni e passaggi che non posso fare io)
1. **Dove pubblicare.** L'indirizzo scritto ora è `https://github.com/LowSkyy/EosOS/releases/latest/download/latest.json`. **Il repository è privato** (richiesta anonima → 404): finché lo è, EosOS non può leggere il feed. Strade: rendere pubblico il repository (o crearne uno pubblico solo per le release), oppure ospitare i tre file altrove in https e cambiare `endpoints` in `tauri.conf.json`.
2. **La chiave privata.** È in `C:\Users\Raffaele\.tauri\eosos-updater.key` (senza password, **fuori dal repository**). Fanne una copia sicura: **se la perdi non potrai più firmare aggiornamenti accettati dalle copie già installate**; se la rubano, chiunque potrà firmarne. La pubblica è in `tauri.conf.json`.
3. **Pubblicare una versione:** alza `version` in `tauri.conf.json` (e `Cargo.toml`), poi `TAURI_SIGNING_PRIVATE_KEY="$(cat <file-chiave>)" TAURI_SIGNING_PRIVATE_KEY_PASSWORD="" npx tauri build`, poi `scripts\make-update-feed.ps1 -BaseUrl https://…/releases/download/v<versione>` (scrive in `dist-update\` il setup, il `.sig` e `latest.json`), poi carichi quei file. Nulla viene pubblicato dagli script.
